# 从这里开始：UR7e + PX6D 运行说明

这份文档是工程的最短操作入口。第一次使用时先完成离线测试和模拟，不要直接启动真机运动。
当前代码已按 `sensor → preprocessing → features → policy → robot → logging` 分层；第一次阅读
请配合 [ARCHITECTURE.md](ARCHITECTURE.md)。旧兼容模块已打包到 `old/*.tar.gz`，实际实现位于职责目录，常用运行命令不变。

## 1. 进入工程并安装 Python 3.12 环境

先检查版本：

```bash
cd /home/user-linux/robotics_cs/ur7e_px6d_contour
python3 --version
```

`ur-rtde` 当前提供的 Linux CPython wheel 最高到 Python 3.12。本机系统 Python 是 3.14，直接
执行 `python3 -m venv` 后安装会出现：

```text
failed-wheel-build-for-install
Failed to build installable wheels: ur-rtde
```

不要在 Python 3.14 环境中反复编译。下面使用 `uv` 单独安装 Python 3.12，不替换系统 Python，
也不删除已有 `.venv`：

```bash
cd /home/user-linux/robotics_cs
curl -LsSf https://astral.sh/uv/install.sh -o /tmp/install-uv.sh
sh /tmp/install-uv.sh
~/.local/bin/uv python install 3.12
~/.local/bin/uv venv --python 3.12 .venv312
source /home/user-linux/robotics_cs/.venv312/bin/activate
unset PYTHONPATH
cd /home/user-linux/robotics_cs/ur7e_px6d_contour
~/.local/bin/uv pip install -r requirements.txt
```

这里有意把环境创建在 `/home/user-linux/robotics_cs/.venv312`，即工程目录的上一级。不要在
`ur7e_px6d_contour` 内使用 `source .venv312/bin/activate`，因为那里没有这个目录。

安装后确认解释器和 `ur-rtde`：

```bash
python --version
python -c "import rtde_control, rtde_receive; print('ur-rtde OK')"
```

应显示 Python 3.12.x 和 `ur-rtde OK`。如果只想运行离线模拟，可以暂时不安装 `ur-rtde`：

```bash
python3 -m venv .venv-sim
source .venv-sim/bin/activate
python -m pip install numpy matplotlib Pillow PyYAML pyserial pytest
```

以后重新打开终端，完整工程使用：

```bash
cd /home/user-linux/robotics_cs/ur7e_px6d_contour
source /home/user-linux/robotics_cs/.venv312/bin/activate
unset PYTHONPATH
```

本机终端启动脚本加载了 ROS 2 Lyrical，并把 Python 3.14 的 ROS 包目录写入 `PYTHONPATH`。
本工程不使用 ROS，因此激活 Python 3.12 环境后要清除该变量。中文菜单也会自动为它启动的
测试和工具清除该变量，避免加载 ROS 的 `launch_testing` pytest 插件。

## 2. 第一次运行：只运行安全菜单

```bash
python3 run_project.py
```

菜单内容：

```text
1. 检查代码
2. 运行模拟闭环并生成可视化图
3. 只读取 PX6D
4. 只读取 UR7e 当前状态
5. 真实 PX6D + 规则 dry-run
6. 方形/圆形/三角形可拖动实时动画

11. 从当前位置三段安全返回复位点（真机运动）
12. 执行真正的 UR7e + PX6D 轮廓扫描（真机运动）
0. 退出
```

菜单 1～10 不发送机器人运动命令；菜单 11 是独立复位，菜单 12 是正式真机扫描，二者会在启动
前要求额外确认词。完整且最新的真机顺序以 [操作文档.md](操作文档.md) 为准。


当前预期结果：

```text

```

```bash
python3 run_simulation.py --no-gui
```

SPACE 暂停/继续，Q 停止，R 重新开始，ESC 停止并关闭。恢复辅助射线只在恢复期间显示。
成功显示 FULL LOOP COMPLETED；提前停止、超时、LOST 显示 LOOP FAILED 并打印原因。
当前结果在 `simulation_outputs/full_loop_square.png`，历史图和日志在同名时间戳目录。
离线入口不需要真实 PX6D，菜单 3 才会检查真实串口。

## 3. 硬件只读验证

只有设备已经连接并确认现场安全后，才依次运行菜单 `3 → 4 → 5`。

### 读取 PX6D

```bash
python3 tools/check_px6d.py --samples 500
```

它只读取固件和六维 F/T，不清零传感器、不连接机器人。遇到串口权限、timeout、CRC 或设备路径
错误时，应先排除故障。

PX6D v1.0.1 的 USB CDC 接口在打开后需要约 2 秒稳定时间，工程会自动等待；数据请求也会按
`sensor.poll_rate_hz` 节流，不能删除这段等待或用无间隔循环连续发送请求。

### 读取 UR7e 状态

```bash
python3 tools/check_rtde.py
```

它只创建 RTDE Receive 接口，读取 TCP pose/speed、active TCP、robot mode 和 safety mode，
不创建控制接口、不发送运动指令。

### 读取示教器当前 active TCP offset

启用示教器的 Remote Control 后运行菜单 `9`，或执行：

```bash
python3 tools/read_active_tcp.py
```

工具建立 RTDE Control 接口，只调用 `getTCPOffset()`，不会发送运动或 `setTcp()`。先在示教器
确认该 TCP 确实对应探针尖端；确认正确后才把输出写入 `config.yaml` 的 `tcp.offset`。更换
active TCP 后必须重新执行 P0/P1 标定。

### 真实 PX6D + dry-run

```bash
python3 main.py --sensor real
```

这个模式读取真实 PX6D，但 TCP 仍由电脑模拟，UR7e 不会连接或运动。它用于验证传感器数据、
预处理、阈值、坐标方向和状态机；不能证明真机运动方向正确。

## 4. 标定正式扫描起点 P0 和初始扫描方向

运行菜单 `7`，或直接执行：

```bash
python3 run_calibration.py
```

这个工具用 RTDE Receive 读取 pose/speed，并用 RTDE Control 只读取 active TCP；不会向 UR7e
发送运动或 `setTcp` 命令。按以下顺序操作：

1. 用示教器把探针尖端 active TCP 安全地移动到扫描起点 P0，保持静止；
2. 输入：

```text
SAVE_P0
```

3. 继续用示教器沿希望正式扫描的方向主要在 XY 平面移动一小段，到达 P1；
4. 保持静止并输入：

```text
SAVE_DIRECTION
```

标定完成时机器人仍停在 P1。程序不会把 P1 当作扫描起点；正式 execute 启动时若 TCP 不在
P0，会先按三段安全路径自动返回 P0，通过到位检查后才允许输入 `START`。

程序自动计算：

```text
dx_raw = P1.x - P0.x
dy_raw = P1.y - P0.y
scan_direction_xy = [dx_raw, dy_raw] / sqrt(dx_raw² + dy_raw²)
```

P0/P1 的 XY 距离必须达到 `config.yaml` 中的
`min_direction_calibration_distance`，Z 差不得超过
`max_direction_calibration_z_difference`。不满足时不会保存方向，程序会等待你重新移动 P1 并
再次输入 `SAVE_DIRECTION`。

P1 只是方向参考点，不是轮廓采样点，也不是机器人正式扫描必须经过的第二个点。P0 的 Z 和
姿态分别保存为 `fixed_z` 和 `fixed_orientation`。

当前正式扫描速度配置为：SEARCH `0.009 m/s`、PROBE `0.003 m/s`、沿轮廓 TANGENT
`0.006 m/s`、RETRACT `0.006 m/s`，均为原设置的 3 倍，并且没有超过
`robot.max_tcp_speed: 0.015 m/s`。

当前初始 SEARCH 最大距离为 `1.500 m`（150 cm）。以 `0.009 m/s` 搜索完整距离约需
167 秒。该距离只是软件允许的最大搜索路程，不代表机器人在当前 P0 和方向下
一定具备完整 1.5 m 的可达空间，运行前必须在示教器中确认整条路径可达且无奇异点、关节限位或碰撞。

根据 2026-09-07 真机日志，未接触段平面扰动力保持在约 `0.45 N` 以下，接触阈值现设为
`1.0 N`。新 policy 只用 Fxy 模长做接触/安全，不用 `probe_direction_sign` 或单帧力方向
推导边界切线；切线来自多个 TCP contact poses 的局部 PCA。

正式 execute 的 `max_boundary_points` 和 `max_runtime_sec` 均设为 `null`：一旦接触目标并进入
轮廓跟随，不再因为点数或运行时间自动正常结束，而是持续执行
`PROBE → RETURN SAME ANCHOR → UPDATE LOCAL BOUNDARY → TANGENT STEP`，直到用户按 Q。mock dry-run 已改为正方形整圈验证，完成后自行结束，模拟时间上限为 120 秒。安全阈值、通信异常、UR 安全状态、ESC/Ctrl+C、TARGET_SEARCH
最大距离以及丢失目标仍可停止运动，它们不是正常扫描完成条件。

普通 PROBE 走满 `0.010 m` 未重新接触时，必须先回到该 probe 自己的 anchor，
再从这个已观测自由空间点开始 `BOUNDARY_RECOVERY`。恢复方向以上次成功探测和局部切线预测，
按 `recovery_sector_extents_deg: [20, 50, 90, 130, 170]` 递进扩大局部角域；这是搜索预算，不是已知拐角角度。
所有短射线都从同一 recovery anchor 出发并返回它。

候选接触返回后进入 `BOUNDARY_CONFIRMATION`，从附近 anchor 再做 guarded probes；
默认总计三个有位移、局部拟合稳定且向前的接触点才确认 `BOUNDARY REACQUIRED`。
确认失败会沿已执行的 anchor 折线退回 recovery anchor，不从接触点走对角线。所有阶段均受
`contact_threshold: 1.0 N`、总力/raw F/T 安全阈值和变化率保护。根据
`run_20260907_124418_645953`，正常低力接触建立时实测变化率为 `11.536 N/s`、Fxy 仅
`1.083 N`，所以 `force_rate_limit` 已从过紧的 `10` 调为 `30 N/s`；其他安全阈值未放宽。

完成后的文件结构如下（数值仅示意）：

```yaml
confirmed: true
robot_ip: 192.168.1.10
start_tcp_pose:
  x: 0.10
  y: -0.20
  z: 0.30
  rx: 0.0
  ry: 3.14
  rz: 0.0
direction_reference_tcp_pose:
  x: 0.13
  y: -0.16
  z: 0.302
  rx: 0.0
  ry: 3.14
  rz: 0.0
scan_direction_xy:
  dx: 0.6
  dy: 0.8
fixed_z: 0.30
fixed_orientation:
  rx: 0.0
  ry: 3.14
  rz: 0.0
calibration_timestamp: '2026-09-07T12:00:00+00:00'
```

标定后运行菜单 `8`，或执行：

```bash
python3 tools/check_scan_calibration.py
```

该只读工具打印 P0、P1 和方向，并生成 `scan_calibration_preview.png`。打开图片确认箭头方向：

```bash
xdg-open scan_calibration_preview.png
```

注意：这里的 P0/P1 是“扫描标定点”。`boundary_points.csv` 保存的是另一类轮廓采样数据，不要
把其中的点编号与标定 P0/P1 混淆。

完成方向标定时 TCP 通常仍在 P1。无需先手动回 P0；执行正式扫描命令后，程序会先走三段安全
路径自动返回 P0，到位后才允许输入 `START`。

## 5. 当前现场配置：关闭 workspace，安全返回向上 3 cm

当前实验场地已经人工检查，不使用软件 workspace 长方体限位。`config.yaml` 配置为：

```yaml
workspace:
  enabled: false
  limits:
    x_min: 0.0
    x_max: 0.0
    y_min: 0.0
    y_max: 0.0
    z_min: 0.0
    z_max: 0.0
```

`enabled: false` 时六个 limits 被忽略，正式扫描和返回不会因为这些零值拒绝启动。关闭的只是
工程中的 TCP workspace 软件检查，不影响 UR 控制器自身的安全设置，也不影响固定扫描 Z、固定
姿态、F/T 阈值、通信、急停和保护停止检查。

现场确认沿 UR Base `+Z` 抬升 3 cm 足以让 probe 退出颗粒并避开目标，因此安全返回配置为：

```yaml
safe_return:
  return_lift_distance: 0.030
  startup_bias_sample_count: 100
  return_speed: 0.015
  return_vertical_speed: 0.009
  return_acceleration: 0.030
  return_force_limit: 8.0
  return_torque_limit: 0.7
  return_position_tolerance: 0.0005
  return_orientation_tolerance: 0.0087
  return_segment_timeout_sec: 60.0
  auto_return_after_normal_stop: true
```

`return_lift_distance` 是相对距离，单位为米。每次正常停止后，程序读取实际停止位置 `P_stop`，
计算：

```text
safe_z = P_stop.z + 0.030
```

如果上一次返回中断时 TCP 已经位于 `P0.z + 0.030` 或更高位置，重新运行时会保持当前安全
高度，不会再次叠加抬升 3 cm，也不会发送零距离垂直 `moveL`。

然后执行“当前位置沿 Base +Z 抬升 3 cm → 在该高度移动到 P0 的 XY 上方 → 下降到 P0”。
`0.030` 不是绝对 Z 坐标。顶部横移返回速度现为 `0.015 m/s`，垂直升降速度为
`0.009 m/s`，都是原值的 3 倍；返回 F/T 阈值、路径和误差容差保持不变。

同时还必须确认 `config.yaml` 中的坐标变换、力阈值、探测方向、active TCP、payload/CoG 和 UR
自身安全设置。工程没有机器人本体、容器、探针和线缆的碰撞模型，关闭 workspace 后由现场
检查和 UR 自身安全配置承担空间限制。

## 6. 启动正式扫描

正式扫描的 SEARCH 必须从标定 P0 开始。标定文件必须同时包含 `start_tcp_pose`、
`direction_reference_tcp_pose` 和 `scan_direction_xy`；缺少任意一项都会拒绝 execute 模式。
确认急停可触达、Remote Control 正常、PX6D 正常、自动返回路径中没有人员或障碍物，然后运行：

```bash
python3 main.py --sensor real --execute
```

命令启动后的顺序是：

```text
读取当前 TCP
→ 若不在 P0：Base +Z 抬升 0.030 m
→ 在抬升高度移动到 P0 的 XY 上方
→ 下降到 P0 并检查位置/姿态误差
→ 采集软件 bias
→ 显示标定信息
→ 等待用户输入 START
```

启动返回前会在当前位置静止采集 `startup_bias_sample_count` 个临时偏置样本，只用于这次返回的
增量力监控。到达 P0 后会重新采集正式扫描 baseline，不会把 P1 的临时偏置带入扫描。返回期间
原始 F/T 的 absolute raw 后备阈值仍持续有效。

如果启动返回途中 F/T、RTDE 或机器人安全状态异常，程序立即停止并拒绝进入扫描。到达 P0 后，
终端会打印 `AUTOMATIC STARTUP RETURN TO P0 COMPLETE`。在 `START` 之前，
终端会打印 START TCP、DIRECTION REFERENCE TCP、INITIAL SCAN DIRECTION、FIXED Z 和
FIXED ORIENTATION，并提示 `Initial search direction is defined by P0 -> P1.`。现场核对无误后输入：

```text
START
```

输入正确后才开始发送扫描运动。第一次接触前，SEARCH 沿 P0→P1 标定方向直线扫描；第一次
接触后先回该 probe anchor，再做局部多点初始化；contour-following direction 来自 TCP
接触点几何，不来自单帧 F/T 方向。

## 7. 扫描中如何停止

正式扫描中的两个停止方式含义不同：

### Q：正常停止

在扫描任意位置按 `Q`：

```text
停止当前扫描运动
→ STOP_SCAN
→ 保存停止点 TCP 和 F/T
→ RETURN_TO_START
→ 沿 UR Base +Z 相对抬升 0.030 m
→ 在安全高度移动到 P0 上方
→ 垂直下降到 P0
→ 检查最终位置和姿态误差
→ 保存日志和轮廓图
```

程序不会直接从当前位置直线移动到 P0。每段进入容差后会先停稳并复查，返回期间持续检查
PX6D force/torque、absolute raw F/T、RTDE、TCP speed、机器人急停/保护停和单段 timeout。
当前 `workspace.enabled: false`，所以不执行软件 workspace 限位。

返回成功时显示：

```text
RETURN TO START COMPLETE
```

### ESC 或 Ctrl+C：紧急停止

按 `ESC` 或 `Ctrl+C`，以及发生通信故障、protective stop 或安全阈值超限时：

```text
立即停止机器人
→ 保存当前可用数据
→ 显示当前或最后可读 TCP 和 P0
→ 不执行自动返回
```

紧急停止后不要直接重新运行扫描。先通过示教器和现场检查确认机器人、目标、颗粒、探针、线缆
及通信状态安全。

如果自动返回期间任一检查失败，程序会立即停止后续返回段并显示：

```text
SAFE RETURN ABORTED: 具体原因
```

## 8. 异常后返回独立复位点

只有人工检查现场并确认三段路径安全后，才运行：

```bash
python3 save_reset_pose.py   # 预先在任意安全静止位置保存一次
python3 return_to_reset.py   # 异常排除后，从当前位置返回
```

复位点与保存时的 active TCP 绑定。返回程序先只读并显示当前位置、复位目标、安全高度和路径。
只有输入：

```text
RETURN_TO_RESET
```

才会连接 PX6D 和 RTDE 控制接口，执行“垂直退出 → 安全高度平移 → 下降到复位点”。启动脚本本身
不会直接运动。protective stop、emergency stop、通信问题或 PX6D 故障未排除时不要使用。


其中 `return_status.json` 只在执行过安全返回时生成；某些早期异常可能来不及生成停止快照。
`full_log.csv` 包含扫描和 `RETURN_TO_START` 周期，`boundary_points.csv` 保存轮廓采样点。

查看最新结果：

```bash
latest=$(find data -maxdepth 1 -type d -name 'run_*' | sort | tail -1)

xdg-open "$latest/contour_result.png"
```

需要重新生成诊断图时：

```bash
python3 tools/visualize_run.py --run-dir "$latest"
```

图中安全返回到 P0 的 XY 路径使用独立虚线显示，避免与扫描轮廓混淆。

## 10. 重要限制

- 二维模拟器不是 DEM 或真实颗粒介质模型；
- residual force direction 是 estimated interaction direction，不是真实表面法向；
- 三段安全返回不是碰撞规划，无法检查机器人本体、夹具、箱体和线缆三维碰撞；
- 软件力阈值和停止逻辑不能替代 UR 安全系统、现场风险评估和人工监护；当前 workspace 软件
  限位已按现场决定关闭。
