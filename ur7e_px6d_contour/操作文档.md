# 原离散策略操作细节与历史故障记录

日常唯一主指南是 [从这里开始.md](从这里开始.md)：进入工程并使用已有环境 → `python run_project.py` → 选择编号 → 按提示操作 → 查看实际结果目录。本文保留原离散第 12 项、共用标定与独立复位的细节，不再提供另一套主入口。

**连续第 18 项 Q/Esc/Ctrl+C 均原地停止，不自动返回。以下 Q 返回说明仅适用于原离散第 12 项。** 完整 0～20 编号表以主指南和菜单为准。换探针须先在示教器标定并启用 TCP，再 9 读取并自动保存本地配置、重采 7/13/10 相关标定、8/14/17 离线检查，现场确认后才真机验证；9 将 active TCP 写入 tcp.offset 并保留原配置备份，不能代替针尖标定。

本文历史数值、故障和旧验证说明均不是本轮测试结果。此前菜单改造未修改原控制和返回流程；历史 45.480 ms 下降停稳超时不属于本次速度修订范围。

连续第 18 项当前为：从已保存扫描 P0 沿 P0→P1 方向 `TARGET_SEARCH`，名义速度 **18 mm/s**（历史连续搜索值为 1 mm/s）；接触触发后先请求停止，等待实测速度连续停稳及原接触/方向确认，再以切向 1 mm/s、法向上限 0.5 mm/s 贴边。搜索与贴边分别保护速度，18 mm/s 不用于连续贴边。此次不改原离散第 12 项的速度、操作或返回行为，也不要求因速度修改重做 TCP、P0/P1 或箱体四角标定。日常仍只使用 `python run_project.py`；下层 CLI 全部保留。

## 2. 历史失败记录：active TCP 与本地配置不匹配（原离散）

历史实验中 PX6D 已连接，程序曾在发送运动前发现以下不匹配；这些数值不是本轮读取结果：

```text
active TCP = [-0.00771, -0.0027, 0.24546, 0, 0, -0.785398...]
config TCP = [0.032148..., 0.000189..., 0.267673..., 0, 0, 0]
```

两者不是同一个 TCP。TCP 不同会改变 RTDE 报告的六维 TCP pose，旧 P0 不能直接和新 TCP混用。
程序不执行 `setTcp()`；菜单 9 重新读取实际 active TCP 后保存，不从历史报错复制数值。

处理顺序：

1. 先在示教器确认并启用物理上正确的针尖 TCP；若原配置对应的 TCP 才正确，先在示教器恢复该 TCP。
2. 运行菜单 9，自动读取 active TCP 并写入 `config.yaml` 的 `tcp.offset`；终端打印旧值、新值、配置路径和备份路径。
3. 核对保存结果；工具不调用 `setTcp()`，也不修改扫描、箱体、复位标定或现场验证记录。
4. TCP 变化后重新采集相关 7/13/10 标定，再做 8/14/17 离线检查。

不要只为消除错误而复制数值。应先确认它确实描述当前探针尖端。

## 3. 从任意位置保存复位点

复位点独立于扫描 P0。可把任意一个静止、安全、适合作为返回终点的位置保存为复位点：

1. 用示教器把机器人移动到希望的复位位置并保持静止；
2. 确认此位置适合作为三段路径的最终落点；
3. 运行菜单 10；
4. 核对终端显示的当前 pose、speed 和 active TCP；
5. 输入 `SAVE_RESET_POSE`。

程序保存 `reset_pose.yaml`，其中同时记录六维 `reset_tcp_pose`、保存时的
`active_tcp_offset`、`robot_ip` 和时间。

该工具会建立 RTDE Receive/Control 接口读取状态和 `getTCPOffset()`，但不会调用 `moveL`、
`moveJ`、`speedL`、`setTcp` 或其他运动命令。

即使当前 active TCP 与扫描配置不一致，也可保存绑定当前 active TCP 的复位点；这只为独立
复位提供身份依据，不会让正式扫描绕过 TCP 检查。

## 4. 从任意当前位置返回复位目标

运行菜单 11，按提示操作。

菜单先要求输入 `OPEN_REAL_RESET`。如果存在 `reset_pose.yaml`，程序使用其中的独立复位点；如果
不存在，则自动使用 `scan_calibration.yaml` 中已经保存的扫描起点 P0。随后只读并显示：

- 当前 TCP pose/speed；
- `reset_pose.yaml` 中的目标；
- 当前 active TCP 和复位点绑定 TCP 是否一致；
- 本次计算的安全高度和三段路径。

使用独立复位点时输入 `RETURN_TO_RESET`；回退到已有 P0 时输入 `RETURN_TO_P0`。程序才会运动。
路径为：

```text
当前静止位置
→ 沿 UR Base +Z 到安全高度
→ 在安全高度平移到复位点上方，同时恢复目标姿态
→ 垂直到复位点
→ 校验最终位置和姿态误差
```

安全高度至少同时满足当前点和复位目标的抬升要求。如果当前点已经位于目标安全高度或更高，
不会再次叠加 3 cm。每段开始前和运动中持续检查 PX6D 力/力矩、raw 后备阈值、RTDE 连接、
机器人安全状态、TCP speed、超时和到位误差。

每段发出停止请求后继续采集力和 TCP，等待实测 XYZ 线速度满足控制器原判据（默认 0.0001 m/s，即 0.1 mm/s），再检查停后位置/姿态。该等待使用原单段的剩余时间，不重新增加超时预算。后续观测若又不满足停稳条件，停止保护仍会拒绝下一条运动。`stop request pending measured standstill` 表示停止请求未得到当前速度观测确认，不应通过清除标志或提高阈值绕过。

“任意当前位置”表示软件不要求机器人先位于 P0 或固定 Z；它不表示任意姿态都可达，也不表示
任意三段路径都无碰撞。本工程没有碰撞规划、IK 路径规划或自动避障。执行前必须逐段确认机器人
本体、探针、夹具、箱体和线缆扫掠空间。

复位点绑定 TCP 与当前 active TCP 不同时，程序拒绝运动。扫描配置与当前 TCP 不一致、但复位点
绑定 TCP 与当前一致时，独立复位可以执行；复位完成后仍不能直接正式扫描。

## 5. 重新标定真实扫描 P0/P1

确认 `config.yaml -> tcp.offset` 与示教器 active TCP 一致后，运行菜单 7。

标定工具不会发送运动或 `setTcp` 命令，但会读取 active TCP 并把它写入标定文件：

1. 用示教器移动到扫描起点 P0，保持静止；
2. 输入 `SAVE_P0`；
3. 沿希望开始搜索的 XY 方向移动一小段到 P1；
4. 保持静止，输入 `SAVE_DIRECTION`；
5. 程序保存 P0、P1、P0→P1 单位方向、固定 Z/姿态和 `active_tcp_offset`。

菜单 7 在每次 `SAVE_P0` / `SAVE_DIRECTION` 后独立建立 TCP 读取会话，采样后断开，不跨示教移动复用旧控制接口。SDK 按原默认方式加载辅助脚本；只读取 TCP/位姿，不发送运动或 setTcp，不调用自动 reupload/解锁恢复。输入保存指令前须结束示教移动并保持静止，确认 Remote Control 可用。P1 读取失败时不保存该点，等待明确重新输入 `SAVE_DIRECTION`；输入 `CANCEL` 结束并保留未完成 P0。旧进程已退出的情况需要重新选择 7，重新采集 P0/P1，不能直接把终端打印值补成有效标定。

P1 只定义初始扫描方向，不是第二个扫描点。保存 P0 后旧方向立即失效；P0/P1 之间若 active
TCP 变化，程序拒绝完成标定。

随后运行菜单 8。必须看到正确的 P0、P1、
`scan_direction_xy`、`active_tcp_offset`，并检查生成的 `scan_calibration_preview.png`。

旧版 `scan_calibration.yaml` 没有 `active_tcp_offset`。新版真实扫描会明确拒绝该文件，必须重新
标定，不能手工给旧 P0 猜一个 TCP。

## 6. 原离散真机前检查顺序（连续使用主指南的 13/14/17/18）

每次改 TCP、工具安装、探针、payload 或传感器坐标后，按此顺序执行：

```text
菜单 1  代码测试
菜单 3  PX6D 连续读取
菜单 4  UR7e 状态只读
菜单 9  active TCP 读取并自动保存 config.yaml，核对输出
菜单 10 保存/确认独立复位点（需要更新时）
菜单 7  重新标定 P0/P1
菜单 8  检查标定方向与 TCP 绑定
菜单 5  真实 PX6D + 模拟机器人 dry-run
菜单 12 真正扫描
```

同时必须人工确认：

- 示教器 Remote Control、payload/CoG、安全平面和急停；
- 探针尖端 TCP、PX6D 到 UR Base 的轴向与正负号；
- P0、P0→P1 搜索方向、固定 Z/姿态；
- 搜索和轮廓路径可达，无奇异点、关节限位或碰撞；
- `return_lift_distance` 三段返回空间；
- 力/力矩阈值、速度、加速度和停止减速度已经现场验证；
- PX6D baseline 采集时探针静止并处于约定的无载状态。

历史现场配置曾为 `workspace.enabled: false`；须核对实际配置。若该项为 false，工程不会用长方体 workspace 阻止越界。UR 自身安全配置和现场
风险评估不能由软件阈值替代。

## 7. 第 12 项：原离散策略执行过程

完成第 6 节所有检查后，运行菜单 12（原离散策略）。

使用菜单 12 时先输入 `OPEN_REAL_SCAN`。

注意：正式程序在等待 `START` 之前，可能先让机器人三段返回 P0。因此输入
`OPEN_REAL_SCAN` 之前就必须检查当前点到 P0 的完整返回路径；不能认为未输入 `START` 就一定
不会运动。

程序实际顺序：

1. 在建立机器人控制前校验配置、扫描标定、robot IP 和标定 TCP 绑定；
2. 连接真实 PX6D；
3. 连接 RTDE，并再次读取示教器 active TCP 与 `config.yaml` 对比；
4. 如果当前 TCP 不在 P0，先采集临时静止偏置，再执行三段受力监控返回 P0；
5. 返回到位后采集正式扫描 baseline；
6. 打印 P0、P1、初始方向、固定 Z 和固定姿态；
7. 现场再次核对后输入 `START`；
8. 正式扫描开始：从 P0 沿 P0→P1 方向 SEARCH；首次接触只定位目标。返回后在邻域左、中、右
   分别以 `probe_speed`（数值以实际配置为准）探测，各自返回 anchor。三个新接触点通过间距和
   拟合残差检查后，才进入轮廓跟踪、切向步进和边界恢复。单轮失败会先回到局部探测起点，
   原位置重测一次，再依次尝试两侧窗口；最多四轮、十二次局部探测，初始化总用时上限 120 秒；
9. 扫描中由操作者按 Q 正常结束，或由 ESC/Ctrl+C 紧急停止。

正式扫描不会因为边界点数或总时间自动视为完成；正常结束由操作者按 Q。

## 8. 原离散的停止/返回语义（不能套用到连续 18）

```text
Q
→ 停止扫描并保存停止快照
→ 三段安全返回扫描 P0
→ 保存返回结果和轮廓图
```

```text
ESC / Ctrl+C / RTDE 或 PX6D 故障 / protective stop / 安全阈值超限
→ 立即停止
→ 不自动返回
→ 人工检查现场
```

两个返回目标不同：Q 正常结束扫描返回扫描 P0；异常排除后运行菜单 11，返回独立保存的
`reset_pose.yaml`。

紧急停止或程序异常后，不要立刻重复菜单 12。先在示教器确认停止状态、检查探针/目标/线缆和
故障原因；如果确实需要独立返回，再运行菜单 11。

使用菜单 **19** 选择实际目录并查看/静态回放，不用按时间排序猜最新真机。完整结果选择规则见主指南。

## 10. 常见失败

- `INITIALIZATION_RETRY`：该轮拟合未通过，程序正在按已执行的 anchor 路径回退并重新探测，
  不需要重新输入 START。查看 `contacts`（需要 3/3）、`min_spacing` 和 `residual`。
  历史记录中的残差上限为 0.600 mm；两侧重试最远偏离局部中心 4.5 mm（3 倍 1.5 mm 横向偏移）。
- `local initialization retries exhausted` / `local initialization timeout`：有限恢复仍未取得
  可信方向或已超时，程序停止且不自动返回。这是策略停止原因，不等于示教器物理急停。
  先检查现场，再按菜单 11 的流程返回。受力、通信或机器人安全异常仍可随时终止重试。
- `active TCP does not match config`：回到第 2 节，确认哪套 TCP 物理上正确，统一示教器和配置并
  重新做 P0/P1；不要关闭校验。
- `scan calibration has no active_tcp_offset binding`：这是旧标定，运行菜单 7 重新标定。
- 没有 `reset_pose.yaml`：程序会自动改用已保存的扫描 P0，不再因此报错。
- `reset pose TCP does not match active TCP`：选择保存复位点时的原 TCP，或重新设置并保存复位点。
- PX6D 设备不存在：运行 `ls -l /dev/serial/by-id/`，把实际完整路径写入
  `config.yaml -> sensor.serial_port`。权限、CRC 或 timeout 未排除前不要进入菜单 11/12/18。
- `SAFE RETURN/RESET ABORTED`：机器人已经停止，不会强行继续剩余路径。记录错误和当前 TCP，
  人工检查受力、障碍、RTDE、保护停止、超时及目标可达性后再决定下一步。
