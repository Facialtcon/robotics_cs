# 单点接触实验｜现场操作指南

> **本页只讲怎样做实验。** 不讲代码结构、CSV字段和测试实现；这些请放入单独的开发文档。  
> **真机说明：** 当前文档所述功能基于程序设计及离线测试，不代表已通过真机验证。固定刚性目标的接近速度、阈值和制动余量须在现场核验。

## 这个程序做什么

固定一个目标接触参考点 **P_ref**，再示教若干个不同方向的起点 **P0-A、P0-B、P0-C……**。选择一个 P0 后，机器人在确认安全的前提下自动准备到实验起点，随后沿着指向 P_ref 的 **XY方向**接近目标。**检测到处理后 Base Fxy 首次达到设定阈值就请求制动；不会因为到达 P_ref 的坐标就认定接触成功。** 停稳后保存完整力和TCP运动记录。

- **P_ref：** 所有实验共用的 XY 参考位置、实验 Z 高度，以及用于推导统一竖直姿态的参考姿态。
- **P0：** 示教时只取 **X、Y** 决定实验起点；示教时的 Z 和姿态不决定实验起点。
- **实验姿态：** 自动计算探针轴朝 Base −Z 的统一姿态；前提是探针轴标定和Base方向正确。
- **实验范围：** 暂时不使用颗粒介质，不执行轮廓跟踪或丢边找回。

## 0. 启动前先确认

1. 目标、夹具已经固定，探针TCP标定正确，人员和周边设备不处于预期运动区域。
2. 检查 `config.yaml`、`single_point_experiment.yaml`。**当前默认会继承原工程参数，包含默认18 mm/s接近速度、1 N接触阈值、100 mm搜索距离等。不能把这些数值当作固定刚性目标已验证的安全值。**
3. 真机运行前，`single_point_experiment.yaml` 中的 `site_validation_note` 需要填写现场核验信息。工作空间和自定义看门狗开关也应检查；文件原值为关闭，不能误以为已启用。
4. 你之前的Linux环境使用仓库根目录的 `.venv312`。下面用对应的Python路径举例；**若本机环境已改变，以 `which python` 或当前实际虚拟环境为准**。

```bash
cd /home/user-linux/robotics_cs/ur7e_px6d_contour_clean
/home/user-linux/robotics_cs/.venv312/bin/python run_single_point_contact.py --execute
```

运行该命令会进入单点实验菜单；**选择菜单项本身不应直接触发机器人运动**。

## 1. 第一次使用：先标定

**① 标定 P_ref（菜单 1）**

- 示教器切到 **Local（本地）**，人工移动探针，使TCP位于选定的固定接触参考位置；停稳。
- 电脑选择 `1`，按提示确认读取。
- 检查终端打印的 **P_ref 的 X、Y、Z（mm）**和保存结果。标定是只读操作，不应发送机械臂运动指令；**看到“保存并回读校验成功”后才算完成**。
- **注意：** P_ref 的 Z 是以后所有实验的统一高度。务必核对高度，不要只看XY。

**② 新增 P0（菜单 2，可重复）**

- 保持 **Local**；手动把TCP移到希望从该方向接近的空间位置，停稳。
- 选 `2`，给这一组取名 `A`、`B`、`C` 等。
- **只使用本次示教位姿的 X、Y**；其 Z 和姿态仅保留在记录中。
- 检查程序显示的接近方向，以及实际将采用的实验起点 `[P0.x, P0.y, P_ref.z, 统一竖直姿态]`。
- 核验对应接近轨迹不会先碰到目标其他部位或夹具，并按提示填写路径核验依据。依据留空时，文档规定该组可保存坐标但**不能用于真机运动**。
- 收到明确成功信息后再示教下一组。

**③ 查看（菜单 3）**

只需看简洁表格：P_ref XYZ、各组P0 XY、接近角度、保存状态、路径核验状态。**不需要直接阅读整份JSON。**

> 修改/删除P0：菜单 `4`。已存在P0组时，文档规定不能直接重标P_ref；确需改变共同参考点，应先妥善备份旧标定，再处理原P0组。

## 2. 开始一次实验（菜单 5）

1. 示教器切为 **Remote（远程）**。选择 `5` 和要用的 `P0-A/B/C`。程序应确认Remote状态；若无法确认，不应执行自动运动。
2. 查看并现场核验程序显示的**完整准备路径**和抬升/旋转空间，按单独的 Enter 授权。既定抬升30 mm并不自动代表不会碰撞。
3. 在确认后，程序准备动作应按顺序进行：**抬升 → 探针自动竖直朝下 → 移到所选P0的XY上方 → 空载采零 → 下降到P_ref的Z高度 → 检查停稳与无接触**。
4. 输入本次接近速度。**菜单输入单位是 mm/s；命令行 `--speed` 的单位是 m/s。** 不要用未经核验的默认速度直接试撞固定刚体。
5. 程序记录至少1秒静止数据。再次确认方向及现场状态，按 Enter **正式开始XY接近**。
6. 程序监测 **Base Fxy**；首次达到实验阈值时请求制动，并记录实际停稳后的数据。若达到距离/时间上限仍无接触，应按无接触结束，而非报告接触成功。

运行时 `Q`、`Esc` 或 `Ctrl+C` 用于请求中止；如遇迫切危险，应使用现场物理急停。**软件请求停止不等于TCP瞬间停止。**

## 3. 再做下一组 / 返回P0

- 换方向时，重新选择另一组 **P0**，核验新路径后按流程执行。
- 菜单 `6` 为**返回指定P0**：切到 Remote，选择组，核验并确认返回路径后才执行。返回目标同样采用该组XY、P_ref的Z和统一竖直姿态。
- 返回路径可能经过固定目标和夹具；若无法确认安全，请使用示教器在Local下手动移至安全位置，**不要强行自动返回**。

## 4. 实验结束后看哪里

每次实验会建立独立目录：`data/real/single_point/run_*`。

| 想看什么 | 文件 |
|---|---|
| 本次是否接触、触发力、制动/停稳时刻与位置 | `single_point_result.json` |
| 完整TCP实际轨迹、六维力、速度等逐帧数据 | `samples.csv` / `full_log.csv` |
| RTDE实际下发的速度指令与时间 | `tcp_commands.csv` |
| 使用了哪个参考点/P0、参数与零偏 | `single_point_calibration_snapshot.json`、`config_snapshot.yaml`、`air_zero.json` |
| 轨迹、力、实际/指令速度的可视化 | `实验回放.html` |

实验重点比较：**接触前实际TCP速度、接触力的方向及峰值、阈值触发到停稳之间的位移和时间**。指令速度与实际速度的时间戳不同，不能简单当作完全同步的数据。

## 5. 常见卡点

| 现象 | 首先检查 |
|---|---|
| 点了菜单3输出几百行数据 | 这是旧版菜单直接打印完整JSON的问题，应改成摘要表格 |
| 标定成功与否不明确 | 是否明确显示“保存成功＋回读校验通过＋保存路径” |
| 标定阶段提示切Remote | 标定只读位姿，按文档可在Local完成；若读取失败，应查看具体RTDE/网络错误 |
| 运动阶段无法开始 | Remote是否明确确认、目标P0及完整路径是否已核验、现场核验字段是否填写 |
| 明明想换P0却要求Z/姿态相同 | 检查是否仍运行旧版单点程序；当前设计只取各组P0的XY |
| 还没接触就到距离上限 | 检查P0方向、真实目标相对位置、每组路径与距离预算 |
| 到达P_ref坐标仍然运动 | P_ref本来不是到位停止点；正常接触停止依赖Fxy阈值，另有独立行程限制 |
